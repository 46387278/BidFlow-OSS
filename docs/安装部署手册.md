# BidFlow 投标工作台 · 安装部署手册

> 版本 v1.0.1 ｜ 编写日期 2026-10-19 ｜ 适用系统 Windows 10 / 11（64 位）
> 本手册写的每一步都在本机实跑过，命令可直接复制。标注「未验收」的条目表示未做过独立复现。

---

## 一、推荐部署架构与选择理由

### 1.1 开源单机版部署

| 形态 | 客户要做到 | 我方人工 | 数据在哪 | 适用 |
|---|---|---|---|---|
| **A 单机（推荐首发）** | 双击 start.bat | 0 | 客户本机 | 一家客户一台电脑，最常见 |
| C 我方服务器多客户 | 无 | 需加鉴权与租户隔离（当前**没有**） | 我方服务器 | 未实现，见 §9 |

**为什么推荐 A**：招标文件、资质原件、报价这些是客户最敏感的数据，放客户自己机器上，一句「我们看不到你的文件」就能说清，不需要任何合规解释。同时单机形态没有并发、没有账号体系、没有多租户隔离，工程上最少出错。


### 1.2 组件构成

```
浏览器（客户操作界面）
      │  HTTP 127.0.0.1:8080
src/app.py（单文件 HTTP 服务 + sqlite 任务台账）
      ├── core/bid_engine.py      读 docx → 评分表结构化
      ├── core/redline_engine.py  废标条款抽取与归类
      ├── core/plan_engine.py     评分细则 → 方案计分点骨架
      ├── core/pipeline.py        要求台账 R/S/Q/F 编号
      ├── core/writer.py          台账 + 内容块 → 初稿 docx
      ├── core/docx_out.py        纯标准库写 OOXML
      └── core/radar.py           需求库 → 项目表
可选外部程序：Chrome 或 Edge（仅用于把 HTML 转成 PDF）
```

## 二、最低可用配置

| 项 | 最低 | 建议 | 说明 |
|---|---|---|---|
| CPU | 双核 | 四核 | 解析是纯文本处理，不吃 CPU |
| 内存 | 4 GB | 8 GB | 单份 200 页 docx 峰值 < 300 MB |
| 硬盘 | 2 GB 空闲 | 20 GB | 每份标书产物约 20–40 MB（含 PDF） |
| 显示器 | 1366×768 | 1920×1080 | 台账表宽，屏幕小了要横向滚动 |
| 网络 | **不需要** | 按需 | 系统本身不联网；只有升级、拉取新需求库时才需要 |

实测参考：一份 1.2 MB、2,344 段落的招标文件，拆标约 0.8–1.0 秒；同时出 3 个 PDF 时约 8–10 秒（时间花在 Chrome 上）。

| 软件 | 版本要求 | 实测版本 | 备注 |

## 四、AI 工具 / 模型的选择与配置

**v1.0 不调用任何大模型。** 三个结果全部由确定性规则引擎产出，这也是「同输入同输出」的前提。

因此：

- 不需要 OpenAI / 通义 / 文心 任何账号；
- 不需要 API Key；
- 不产生任何按次调用费用；
- 处理过程中**没有任何数据离开本机**（系统不发外部网络请求，可用防火墙验证）。

如果客户要求「文字更顺」而接入大模型润色，属于 v1.1 的可选项，接法与本版本的边界见 `docs/常见故障与修复.md` 第 6 节与验收报告 §G。

## 五、目录结构、环境变量与权限

### 5.1 目录结构（解压后原样保留）

```
BidFlow_v1.0\
├── start.bat                 双击启动
├── self_check.bat            自检（不联网、不开服务）
├── requirements.txt          空的——零第三方依赖
├── config\
│   ├── config.example.json   配置模板
│   └── config.json           首次启动自动从模板复制生成
├── src\
│   ├── app.py                HTTP 服务入口
│   ├── core\                 七个规则引擎
│   └── web\index.html        操作界面
├── data\
│   ├── requirements.csv      需求库（71 条）
│   ├── blocks.md             方案内容块库（21 块）
│   └── sample\               两份真招标文件样本（用于验收复现）
├── tests\                    三个验收脚本
├── docs\                     本手册与其余三份文档
└── output\                   所有产物按任务号分目录存这里
    └── jobs.db               任务台账（sqlite）
```

### 5.2 配置项

`config/config.json`（不存在时程序读 `config.example.json`，启动脚本会自动复制一份）：

| 键 | 默认 | 说明 |
|---|---|---|
| `host` | `127.0.0.1` | 只允许本机访问 |
| `port` | `8080` | 端口被占用时改这里，或启动时加 `--port 8081` |
| `data_dir` | `data` | 相对包根目录，也可写绝对路径 |
| `store_dir` | `output` | 产物目录，建议放在空间充足的盘 |
| `pdf_default` | `true` | 是否默认出 PDF（实际取决于有没有 Chrome/Edge） |

**环境变量：不需要设置任何环境变量。** 程序不读 `PATH` 以外的外部变量；把整个目录拷到 D 盘、E 盘都能直接跑（实测：目录整体搬迁后无需改动）。

### 5.3 权限与三个前置检查

- 运行账号需要 `output\` 与 `data\` 的**读写**权限，其余目录只读即可；
- 不需要管理员权限，不需要注册表，不需要装服务；
- **不要放在 `C:\Program Files\`**（见 Step 2 说明）。

**装之前先花 2 分钟做这三件事，能省掉 90% 的现场故障：**

**① 查 8080 端口有没有被占**

在任意命令行窗口执行：

```bat
netstat -ano | findstr :8080
```

- **没有任何输出** = 端口空着，直接用默认配置；
- **有输出**（例如 `TCP 0.0.0.0:8080 ... LISTENING 4521`）= 被占了，最后那个数字 4521 是占用它的进程号。不用去关它，改用 8088 端口即可（见 Step 4）。

**② 确认要放的目录能写**

把 zip 解压到目标文件夹后，在里面新建一个文本文档试试。建不出来 = 这个目录没写权限，换 `D:\` 或 `C:\Users\<你>\Documents\`。

**③ 杀毒软件先加白名单（可选但强烈建议）**

360 / 火绒 / 电脑管家可能把 `python.exe` 的监听行为或 `.bat` 判为可疑。装之前：
- 打开杀软 → 设置 → 白名单/信任区 → 把整个 `BidFlow_v1.0` 文件夹加进去。

**如果已经被拦了怎么办：**
- 弹窗选「允许」→ 一般就过了；
- 如果点了「阻止」或文件被隔离：打开杀软的「隔离区」→ 找到 `start.bat` / `python.exe` → **恢复** → 加入信任区 → 重跑；
- 公司规定不能改杀软设置时，让 IT 加白名单，或**换一台不装杀软的机器做演示**（本系统不联网，不涉及风险）。

## 六、安装步骤（按顺序执行）

**Step 1 装 Python**

1. 打开 <https://www.python.org/downloads/windows/> 下载 3.8 以上 64 位安装包；
2. 安装第一屏**必须勾选** `Add Python 3.8 to PATH`；
3. 装完开「命令提示符」，输入：

```bat
python -V
```

应输出 `Python 3.x.x`。若提示「不是内部或外部命令」，说明没勾 PATH，按下面**任选一种**补救：

**补救 A（推荐，2 分钟）**：重新运行 Python 安装包 → 选 `Modify`（修改）→ 勾上 `Add Python to environment variables` → 完成。不用重装，已装的东西不会丢。

**补救 B（手工加 PATH）**：
1. Win 键搜「环境变量」→ 打开「编辑系统环境变量」→ 右下角「环境变量」；
2. 在「用户变量」里找到 `Path` → 双击 → 「新建」→ 填入 Python 安装目录，通常是：
   `C:\Users\<你的用户名>\AppData\Local\Programs\Python\Python313\`
   和
   `C:\Users\<你的用户名>\AppData\Local\Programs\Python\Python313\Scripts\`
3. 确定保存，**关掉所有命令行窗口重开**，再 `python -V`。

> 找不到 Python 装在哪？在开始菜单搜索 `python`，右键 → 打开文件位置，就能看到目录。
>
> 如果公司电脑被组策略锁住、上面两步都做不了，**不用管理员权限也能跑**：直接告诉部署方，用"绿色安装"方式把 Python 解压到 `D:\Python\`，然后按补救 B 加 PATH（用户变量不需要管理员）。

**Step 2 解压**

1. 把 `BidFlow_v1.0.zip` 解压到任意位置，例如 `D:\BidFlow_v1.0\`。
2. **解压完先做这一眼判断**：打开解压出来的文件夹，你应该**同一层**看到下面这 6 个东西：

```
start.bat        self_check.bat     requirements.txt
README.md        config\            src\
```

看到就对了，往下走。

- 如果看到的是**又一个 `BidFlow_v1.0` 文件夹**（套了两层），进去一层再判断；
- 如果看到 `start.bat` 孤零零躺在「下载」文件夹里，和其他下载文件混在一起——**这是解压时选了"解压到当前文件夹"**，请新建一个空文件夹重解一次。

> **路径能不能带中文和空格？**
> **能。** 2026-10-19 用 `D:\投标工作\2026年\BidFlow v1.0\` 这种带中文和空格的路径实跑过自检，36 项全过。
> 但不要把包解压到**桌面**或**下载**文件夹——那里文件多、容易被清理、路径也长。建议单独建一个 `D:\投标工作\BidFlow\`。
>
> **绝对不要解压到 `C:\Program Files\` 或 `C:\Program Files (x86)\`。** 这两个目录普通账号没有写权限，`output\` 写不进、`config\config.json` 也生成不出来。程序"不需要管理员权限"指的是**不需要装服务、不改注册表**，不等于可以放进系统目录。

**Step 3 自检（先不启服务）**

```bat
cd /d D:\BidFlow_v1.0
self_check.bat
```

期望看到三段 `通过 N 项，失败 0 项`，最后一行 `RESULT: ALL PASS`。
自检不联网、不开端口，纯粹验证引擎与数据是否完好。

**Step 4 启动**

```bat
start.bat
```

看到如下输出即成功，浏览器会自动打开：

```
========================================================
 投标工作台  v1.0.1   零依赖 · 数据不出门
 地址   http://127.0.0.1:8080/
 数据   D:\BidFlow_v1.0\data
 产物   D:\BidFlow_v1.0\output
 PDF    可用
========================================================
```

浏览器没自动打开时，手工访问 `http://127.0.0.1:8080/`。

**如果起不来**，黑窗口里会直接说中文原因（不会只甩一堆英文报错）。最常见的是端口被占：

```
[错误] 端口 8080 起不来：[WinError 10013] ...
  怎么换端口：python src\app.py --port 8088
```

按提示换成 8088 即可（`--port` 命令行参数优先于配置文件）：

```bat
python src\app.py --port 8088
```

换完地址变成 `http://127.0.0.1:8088/`。**注意：`start.bat` 里写死了 8080，如果长期要用别的端口，请直接改 `config\config.json` 里的 `"port": 8088`，然后仍然双击 `start.bat`。**

**怎么关（重要）**：

- 正在跑任务时**不要**点右上角 ✕ 强关，任务是同步执行的，关掉可能让任务停在 `running` 状态；
- 正确做法：在黑窗口里按 **`Ctrl + C`**，等它显示「已停止」再关窗口；
- 如果已经强关了：重新启动时程序会自动把上次遗留的 `running` 任务标成 `interrupted`，不会损坏台账，重跑该任务即可。

**每天要开机手动启动一次**：v1.0 没有做开机自启（见第十二节）。投标部的同事每天早上双击一次 `start.bat` 即可，或者让 IT 做一个开机启动快捷方式放到「启动」文件夹（Win+R 输入 `shell:startup`）。


**Step 5 冒烟验证（3 分钟）**

1. 界面点「拆标」→ 选 `data\sample\fuyong.docx` → 应返回 5 个文件（无 PDF）或 8 个（有 Chrome）；
2. 打开 `1-废标红线档.html`，页面顶部应有红字责任声明，正文应有 46 条；
3. 界面上「写初稿」→ 应下载到一份 docx，用 Word 打开，标题区应写「技术方案（AI 初稿）」，应有 19 个 `S-0xx` 小节。

三步都对，安装完成。详细判定标准见 `docs/三项功能验收手册.md`。

## 八、日志、备份、升级与恢复

### 8.1 日志

- **控制台日志**：`start.bat` 那个黑窗口就是日志，含每个请求的 HTTP 状态与耗时；异常会打印完整 traceback。
- **没有日志文件**（v1.0 已知缺口）。窗口一关，日志就没了。需要留存证据时，把窗口内容复制出来，或改用：

```bat
python src\app.py --port 8080 >> output\server.log 2>&1
```

- **任务台账**：`output\jobs.db`（sqlite），每次请求一行，含任务号、类型、文件名、状态（done/failed/interrupted）、耗时、结果摘要。查最近 10 条：

```bat
python -c "import sqlite3;c=sqlite3.connect(r'output/jobs.db');[print(r) for r in c.execute('select id,kind,status,name,ms from jobs order by created desc limit 10')]"
```

### 8.2 升级

1. 先备份（见 8.4）；
2. 用新包覆盖 `src\` 与 `docs\`；
3. **不要覆盖** `data\requirements.csv`（那是业务数据）与 `output\`；
4. 跑 `self_check.bat`，三段全过才算升级成功。

### 8.3 常见错误

见 `docs/常见故障与修复.md`，按「现象 → 原因 → 处理」查。

### 8.4 备份与恢复

见 `docs/数据备份与恢复.md`。一句话版本：**整目录拷走即可，`output\` 和 `data\` 是全部业务数据。**

### 8.5 换电脑 / 迁移到新机器

**要带走什么**：整个 `BidFlow_v1.0` 文件夹（含 `output\` 和 `data\`），拷到 U 盘或网盘即可。

**新机器上要做三步**：
1. 装 Python（新机器上一次，见 Step 1）；
2. 把文件夹拷过去，**路径可以变**（D 盘换 E 盘、中文路径都行）；
3. 跑一次 `self_check.bat`，看到 `ALL PASS` 就说明数据和引擎都完好。

**唯一的坑**：如果你以前在 `config\config.json` 里把 `data_dir` / `store_dir` 写成了**绝对路径**（例如 `D:\BidFlow_v1.0\data`），换盘后要改成新路径，或者干脆删掉这两行用默认值（默认是相对路径，跟着文件夹走）。

**卸载**：直接删掉整个文件夹即可。不写注册表、不装服务、不占系统目录。

### 8.6 服务中断了怎么看

打开界面右上角的「任务」列表，每条任务有状态：
- `done`：完成，产物在 `output\<任务号>\`；
- `failed`：失败，摘要里写了原因；
- `interrupted`：进程被强杀或电脑断电，该任务产物可能不全，**直接重跑一次即可**，不会互相污染。

## 十一、客户资料如何存储、哪些数据会离开本机

| 数据 | 存在哪 | 是否外发 |
|---|---|---|
| 上传的招标文件 | `output\<任务号>\source.docx` | **否** |
| 生成的报告 / 台账 / 初稿 | `output\<任务号>\` | **否** |
| 需求库 | `data\requirements.csv` | **否** |
| 任务台账 | `output\jobs.db` | **否** |
| 客户企业资料 | 系统**不采集**，只在初稿里留【待填】位置 | 否 |

验证方法（建议交付时当着客户做一次）：拔掉网线，跑一遍拆标 + 写稿 + 雷达，三个结果全部正常产出。**这比任何承诺都有效。**

唯一例外：`/api/draft` 之前需要先有拆标产物，全部在本机完成；系统不会在后台回传任何统计信息（代码里没有出站 HTTP 调用，可检索 `urllib.request` 只出现在测试脚本中）。

# 常见故障与修复

> 按「现象 → 先查什么 → 原因 → 处理」查。凡标「已修」的，是本轮验收里真实遇到并修复的。

---

## 一、启动类

### 1.1 双击 start.bat 闪一下就没了

**先查**：改成在命令行里跑，看报错：

```bat
cd /d D:\BidFlow_v1.0
python src\app.py --port 8080
```

| 报错 | 原因 | 处理 |
|---|---|---|
| `'python' 不是内部或外部命令` | 装 Python 时没勾 PATH | 重装并勾选 Add to PATH，或手工加 PATH |
| `ModuleNotFoundError: No module named 'bid_engine'` | `src\core\` 目录缺失 | 重新解压，别只拷 app.py |
| `SyntaxError` | Python 版本低于 3.8 | `python -V` 确认，升级 |

### 1.2 端口被占用

**现象**：`OSError: [WinError 10048] 通常每个套接字地址只允许使用一次`

**处理**：

```bat
netstat -ano | findstr :8080
taskkill /PID <上面查到的PID> /F
```

或换端口：`python src\app.py --port 8081`（同时改 `config\config.json` 里的 `port`，否则 start.bat 下次还是 8080）。

### 1.3 浏览器打开是空白 / 打不开

- 先看黑窗口是否还在跑（窗口关了服务就停了）；
- 确认地址是 `http://127.0.0.1:8080/`，不是 `https`；
- 公司代理可能拦截 localhost：浏览器设置里把 `127.0.0.1` 加入「不使用代理」。

## 二、拆标类

### 2.1 提示「只支持 .docx（.doc 请先另存为 docx）」

**原因**：老 `.doc` 是二进制格式，不是 zip，标准库无法解析。

**处理**：用 Word 打开 → 另存为 → 选择「Word 文档 (*.docx)」→ 重新上传。
**这是本版本的硬限制，没有绕过的办法**（要支持得引入第三方库，与零依赖冲突）。

### 2.2 拆标成功，但「评分项 0、红线 0」

**先查**：这份 docx 是不是**扫描件**（把图片塞进 docx，或用 PDF 转出来的）。

**判断方法**：Word 里 Ctrl+A 全选，如果能选中文字，就是文字版；如果只能选中整块图，就是图片版。

**原因**：图片没有文字层，引擎读到的是空文本。

**处理**：走 OCR 路线（本版本不做）。可先让客户提供原始电子版招标文件，或用 Word 的「图片转文字」、PDF 工具的 OCR 功能转一遍再上传。

### 2.3 提示「拆标失败：File is not a zip file」

**原因**：文件损坏，或把 `.doc`/`.pdf` 改了扩展名冒充 `.docx`。

**处理**：用 Word 打开原件另存一次；仍失败说明文件本身坏了，向发标方重新索取。

### 2.4 分值合计不是 100，被标红

**这是校验提示，不是错误。** 真实招标文件常见两种写法：

- 技术+商务=70，价格 30 分单列（本次两份样本都是这种，合计 70）；
- 全部并入一张表，合计 100。

**处理**：人工确认价格分是否单列；单列就按 70 记录，不要当成 bug 改数据。

### 2.5 红线档里的段落号对不上

**原因**：段落号是「按文档流顺序的第 N 个非空段落」，Word 里看不到段号，需要在 `scoring.json` 或复制原文检索定位。

**处理**：用红线档里的原文片段直接在 Word 里搜，比数段号快。

## 三、写初稿类

### 3.1 提示「该任务没有评分表，请先拆标」

**原因**：写初稿依赖同一任务目录下的 `scoring.json`。

**处理**：先对同一份文件做一次拆标，拿到任务号，再写初稿。不能用雷达任务写稿。

### 3.2 Word 打开提示「文件已损坏，是否修复」

**先查**：

```bat
python -c "import zipfile;print(zipfile.ZipFile(r'output\<任务号>\4-初稿_技术方案初稿.docx').namelist())"
```

应能看到 `[Content_Types].xml`、`word/document.xml`、`word/styles.xml` 三个条目。

- 三个都在 → 文件是合法的，可能是 Word 版本太老（2010 以前），另存一次即可；
- 少了 → 生成过程被中断，重新点一次「写初稿」（会覆盖同名文件）。

### 3.3 某一节是空的 / 只有一句「本节无匹配内容块」

**原因**：内容块库 `data\blocks.md` 里没有与该计分点匹配的块。当前块库按公厕行业写，共 21 块，换行业就会出现大片空节。

**处理**：在 `data\blocks.md` 里按格式补块（`@@ 关键词1 | 关键词2` 开头，下面是正文，`## ` 开头是小标题），保存即生效，不用重启。

### 3.4【待填】太多，是不是没写完

**不是。**【待填】是设计：凡需要客户事实（年限、天数、吨位、品牌、报价）的地方，一律不编，留位待填。**待填数量＝这份初稿离可提交还差多远。**

如果希望减少待填，只能由客户提供对应的企业资料，或由我方把行业常用值写成块（会降低针对性，慎用）。

## 四、雷达类

### 4.1 项目表是空的

**先查** `data\requirements.csv` 是否存在、行数是否为 71：

```bat
python -c "import csv;print(sum(1 for _ in open('data/requirements.csv',encoding='utf-8-sig'))-1)"
```

- 文件不存在 → 包不完整，重新解压；
- 行数变了 → 数据被改过，回滚备份。

### 4.2 筛选条件和结果不符

**原因**：金额字段里混了非数字字符（如「约 120 万」「待确认」）。引擎用正则取第一个数字，取不到按未知处理。

**处理**：把金额列统一成纯数字，单位固定「万元」。

### 4.3 同一个项目出现两次

**已知缺陷**：系统不做去重。当前库有 5 组同名项目（武进城区 3 条、其余各 2 条）。

**处理**：人工在 CSV 里合并；合并规则建议「保留阶段最新、金额最全的一条，其余标阶段=已失效并备注合并去向」。

## 五、运行中类

### 5.1 服务被意外关闭（断电、任务管理器强杀）

**现象（v1.0 已修）**：任务永远显示「running」，产物目录里有半套文件，客户端什么也没收到。

**现在的行为**：重启时自动把 `running` 改成 `interrupted`，摘要写「进程中断，产物可能不完整」。

**处理**：重新上传同一份文件走一次即可（每次任务独立目录，不会覆盖上一次的产物）。

### 5.2 提示「文件超过 80MB 限制」

**原因**：`app.py` 里 `MAX_BODY = 80 * 1024 * 1024`。

**处理**：超大标书先在 Word 里删掉附件图片再上传，或调大该常量（需重新启动）。

### 5.3 磁盘满 / 写入失败

**现象**：返回 `拆标失败：... Permission denied` 或 `No space left on device`。

**处理**：
1. 清 `output\` 下旧任务目录（按日期删，不要删 `jobs.db`）；
2. 确认 `output\` 可写（右键属性 → 安全）；
3. 把 `config\config.json` 的 `store_dir` 指到空间大的盘，例如 `"D:\\BidFlow_data"`。

### 5.4 没有 PDF，只有 HTML

**原因**：本机没装 Chrome 或 Edge，或装在了非标准路径。

**处理**：装 Chrome 即可；或在浏览器里打开 HTML，Ctrl+P 选「另存为 PDF」，效果一致。

## 六、关于接大模型（v1.1 备查）

本版本**不调用模型**。若客户要求润色，接法必须守住四条，否则会把「可回源」变成「不可回源」：

1. **只润色，不改结构**：模型只能改「段落的表达」，不许动标题、编号（S-###）、【待填】标记。技术上做法是分段送、逐段回收、回收后校验编号与占位数量是否与送出一致，不一致就整段丢弃、保留原文。
2. **模型接在客户侧**：客户自己的 API Key，或客户内网的模型网关；我方不代理、不转发、不留存。
3. **不能整份文档送出去**：只送「已生成的正文段落」，不送资质、报价、企业信息。
4. **必须留开关**：关闭时，输出与今天完全一致（这是回归测试的基准）。

费用：按客户实际调用量付给模型厂商，与软件无关。
